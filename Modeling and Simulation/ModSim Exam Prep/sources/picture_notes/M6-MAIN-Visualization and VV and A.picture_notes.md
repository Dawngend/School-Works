### [img/M6-MAIN-Visualization and VV and A-page-25.png](file:///D:/School-Works/Modeling%20and%20Simulation/ModSim%20Exam%20Prep/sources/picture_notes/img/M6-MAIN-Visualization%20and%20VV%20and%20A-page-25.png)
* **Slide Title:** Visualization – Computer Graphics Fundamentals | Overview of Graphics Systems – Computation Stage: 3D Object Representations and Transformations
* **Key Content:**
  * Points and vectors initially reside in 3D Cartesian space $(x, y, z)$ as $3 \times 1$ column or $1 \times 3$ row matrices.
  * In computer memory and graphics pipelines, both are stored as 4-component vectors using **homogeneous coordinates**.
  * Enables representing all affine transformations (translations, rotations, scaling) uniformly as standard matrix multiplications.
  * **Mathematical formulas:**
    $$P = \begin{bmatrix} x \\ y \\ z \\ 1 \end{bmatrix}, \quad \mathbf{v} = \begin{bmatrix} x \\ y \\ z \\ 0 \end{bmatrix}$$
    *(Point has $w = 1$, allowing translation; Vector has $w = 0$, making it invariant to translation).*

### Possible slide errors

1. **Slide 9 — Grammar and terminology error:**
   * The text reads: *"The three axis: X (horizontal), Y (vertical) and Z (middle)."*
   * **Why it is wrong:** The singular word *"axis"* is used instead of the plural *"axes"*. Furthermore, labeling the Z-axis as *"(middle)"* is non-standard and inaccurate in 3D geometry and computer graphics; the Z-axis represents the *depth* or *distance* dimension (perpendicular to the projection screen), not "middle".

2. **Slide 13 — Categorization / Hierarchy error:**
   * The header classifies the slide under: *"Overview of Graphics Systems – Hardware – Input Systems"*.
   * **Why it is wrong:** The slide defines and illustrates a *"Vector display system - graphical output system that was based on strokes"*. A vector display is an **output device/display technology**, not an input system. Placing it under "Input Systems" is a categorization mistake.

3. **Slide 20 — Grammatical error:**
   * The slide defines frame buffer as: *"The picture definition is stored in a memory is called refresh or frame buffer."*
   * **Why it is wrong:** The sentence contains a double predicate error (*"is stored ... is called"*). It should read: *"The picture definition is stored in a memory called the refresh or frame buffer"* or *"The memory in which the picture definition is stored is called..."*.

4. **Slide 21 — Heading syntax error:**
   * The diagram title reads: *"Basic architecture of raster graphics of frame buffer"*.
   * **Why it is wrong:** The phrase *"raster graphics of frame buffer"* is ungrammatical and garbled; it should properly read *"Basic architecture of a raster graphics frame buffer system"* or *"Basic raster graphics architecture with frame buffer"*.

5. **Slide 22 — Omitted color depth assumption and ambiguous unit conversion:**
   * The slide calculates: *"Frame buffer = 640\*480 bits = 307200 bits = 38400 bytes = 38.4 kilobytes"*.
   * **Why it is wrong / incomplete:** 
     1. It assumes $1\text{ bit per pixel}$ (monochrome/1 bpp) without stating this assumption; an uncompressed color framebuffer (e.g., 24-bit or 32-bit true color) would require 24 to 32 times more memory.
     2. It calculates kilobytes using the decimal metric conversion ($38,400 / 1000 = 38.4\text{ KB}$), whereas memory allocations in computer systems and architecture are traditionally computed in binary kibibytes ($38,400 / 1024 = 37.5\text{ KB / KiB}$).

- **Slide Title**: Overview of Graphics Systems – Hardware – Output Systems: Liquid Crystal Displays (LCDs)
- **Operating Mechanism**:
  - Modulates light transmission using molecular polarization rotation rather than shooting electron beams.
  - **Twisted Nematic (TN) Cell Mechanics**:
    - *Zero Field (Off)*: Nematic liquid crystals naturally twist light by $90^\circ$, allowing it to pass through the second perpendicular polarizer (**Transmitted Light**).
    - *Applied Electric Field (On)*: Crystals untwist and align parallel to the electric field; light polarization is unchanged and is absorbed/blocked by the analyzer (**Blocked Light**).

- **Slide Title**: Overview of Graphics Systems – Computation Stage: Synthetic Camera and Projections
- **Coordinate Basis & View Transformation Matrix**:
  - Camera orthonormal basis vectors represented in world space:
    $$\mathbf{u} = \begin{bmatrix} u_x \\ u_y \\ u_z \\ 0 \end{bmatrix}, \quad \mathbf{v} = \begin{bmatrix} v_x \\ v_y \\ v_z \\ 0 \end{bmatrix}, \quad \mathbf{n} = \begin{bmatrix} n_x \\ n_y \\ n_z \\ 0 \end{bmatrix}$$
  - $4 \times 4$ World-to-Camera transformation matrix $\mathbf{M}$:
    $$\mathbf{M} = \begin{bmatrix} 
    u_x & u_y & u_z & -u_x P_{C,x} - u_y P_{C,y} - u_z P_{C,z} \\ 
    v_x & v_y & v_z & -v_x P_{C,x} - v_y P_{C,y} - v_z P_{C,z} \\ 
    n_x & n_y & n_z & -n_x P_{C,x} - n_y P_{C,y} - n_z P_{C,z} \\ 
    0 & 0 & 0 & 1 
    \end{bmatrix}$$
  - Coordinate transformation formula:
    $$\mathbf{P}_{\text{camera}} = \mathbf{M} \mathbf{P}_{\text{world}}$$

- **Slide Title**: Overview of Graphics Systems – Computation Stage: Lighting and Shading - Lights
- **Light Models: Point Light**:
  - Omnidirectional ideal point radiator emitting light equally in all directions from a specific 3D position $(x, y, z)$.
  - **Distance Attenuation Formula**:
    $$I(Q) = \frac{1}{a + bd + cd^2} I_0$$
    - $I(Q)$: Received intensity at surface point $Q$.
    - $I_0$: Source emission intensity.
    - $d$: Euclidean distance from source to point $Q$.
    - $a, b, c$: Constant, linear, and quadratic attenuation coefficients, respectively.

- **Light Models: Spotlights**:
  - Emits a directional conical beam defined by: source location $P$, principal aiming direction vector, and cutoff half-angle $\theta$.
  - Intensity outside the cone cutoff angle is zero ($I = 0 \text{ for } \phi > \theta$).
  - **Angular Falloff Formula**:
    $$\text{Intensity} \propto \cos^e \phi$$
    where $\phi$ is the angle between the cone axis and the ray to surface point, and $e$ is the spotlight concentration/falloff exponent.

* **Key Facts:**
  * Defined as employing an irrelevant model—a model valid for its original purpose or simuland, but misapplied to an unsuitable context (e.g., training on an aircraft simulator calibrated for a different airframe).

  * Consequences match the severity of Type II errors.
  * Associated risk term: **model accreditor’s risk**.
